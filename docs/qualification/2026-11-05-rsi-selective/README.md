# Selective asset research follow-up

The [November 5 pilot](../2026-11-05-rsi-v1.1/README.md) completed with a failed
updating skill mechanism and inconclusive efficacy. Its implementation and
evidence shipped in [PR #121](https://github.com/houllette/lemieux/pull/121),
merged as `f3510351eebbe7679f8016e4f133af015035c992`. CI, Public readiness and
Dependency graph all passed on that merge commit. The parent tracker and
remaining qualification, typed-asset and export issues remain open.

This follow-up addresses the two observed engineering gaps before another
qualification campaign. It changes an explicitly registered experimental asset
lane, with no new default asset-kind authority or persistent activation.

| Change | Offline assertion |
| --- | --- |
| Search admission | A safe, accounted passing baseline invokes no improver and records zero search usage. Unknown or unsafe source evidence also abstains. |
| Procedure applicability | Bounded literal triggers must occur in current public conversation/tool evidence; earlier experience, session/system metadata and JSON escaping cannot manufacture or hide a match. |
| Actual invocation | A matched task sees the existing loader first. A complete body read releases task tools. An undisclosed effectful call is denied until then; host permission denials still apply afterward. |
| Bounded decline | Only one stop continuation is permitted within the original session ceilings. Repeated prompts require a new read; unrelated prompts retain their ordinary catalog. |
| Paged reads | Every page through the final marker is required. Missing, truncated, malformed or oversized framing does not count; appended host feedback does not erase the loader's frame. |
| Early rejection | An unused candidate retains its first failed probe, then receives no second probe, controls or composition executions. |
| Single component | Two candidate probes and two controls suffice. The identical composition references the exact candidate evaluations, with budget stops counted once. |
| Multiple components | Two individually supported components still receive two fresh joint probes, for eight probe executions total. |
| New evidence scope | v8/v3 mechanisms bind the new policy and reject historical v2 receipts or changed execution settings. Every declared kind still needs actual updating-arm use. |
| Planning | The real runner produces a v8/v5 registration without credentials, Docker, an allowance ledger or episodes. Its one-kind, 12-request example reserves 1,001 requests across one seed and twelve targets. |

The failed development assertions were retained in local Temper/log history.
They exposed incomplete page detection, literal-quote matching, undisclosed
write bypass, earlier system guidance supplying a trigger, and duplicated
budget-stop counts before their fixes. Initial
missing-module, unwired-policy and stale-protocol failures are also retained.
These deliberately changing development trees do not supply independent flake
or efficacy observations.

A wider focused run also had one unexpected divergence in the existing
promoted-request accounting test: 48 reported tokens instead of unknown usage.
That case passed in isolation, all three subsequent seeded observations and the
6,078-case ordinary suite. The earlier failure is retained, with no source fix
or cause attributed to it. The 45 seeded checks preceded the final tightening of
metadata exclusion; seven focused cases then checked that change before the
full gate. No passing retry erases an earlier result.

## Offline gate

The [validation record](validation.json) binds the eighteen changed implementation
and test files and retains log hashes for the passing gate, earlier red
regressions, unexpected divergence and deliberately interrupted first gate.
`mix precommit.full` passed: ordinary and coverage runs each passed 6,078 cases
(12 doctests and 6,066 tests), with 11 skipped and 47 excluded. Coverage was
86.72%; Dialyzer reported zero errors. The standalone host passed 123 tests,
the distributed suite passed 25, the packaged consumer compiled and preserved
resume/tightening, all eleven examples checked successfully, and all 80 Python
tests passed.

The [eight benchmark canaries](benchmark-host.json) passed in disposable
containers against this source. The copied apparatus matched all 69 hashes in
the [earlier inventory](../2026-11-05-rsi-v1.1/benchmark-apparatus.json), and its
dependency lock matched the target library. No benchmark-labelled container
remained on the selected engine. The primary benchmark checkout was preserved.
These canaries check host contracts rather than learned efficacy.

Verify the public packet with `shasum -a 256 -c SHA256SUMS` from this directory.

The policy is quality-directed. It cannot retire requests already spent on the
original baseline and does not establish persistent pre-task reuse, transfer or
efficiency. Single-component reuse removes duplicate execution of an identical
intervention; it does not add independent evidence. Scripted providers supply
mechanical controls, not measured model behavior.

No new hosted campaign was executed for this follow-up. The old pilot retains
its frozen code binding, outcomes and refused mechanism. A future hosted run
needs a new registration, an explicitly authorized model/effort and allowance,
and a fresh matching mechanism. Independent efficacy additionally needs a fresh,
separately curated corpus and adequate registered power. Repartitioning exposed
benchmark pools or repeating the graph fixture does not satisfy that gate.
