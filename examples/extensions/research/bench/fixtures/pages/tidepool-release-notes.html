Tidepool release notes

3.5.0

  • Consumers may now replay from a timestamp rather than an offset.
  • The metrics endpoint reports per-partition lag.
  • Fixed a race when two producers created the same topic at once.

3.4.0

Release 3.4.0 introduced the reef compaction mode for cold partitions. Reef mode rewrites a partition into a single sorted segment once it has gone an hour without writes, which cuts replay time for archival topics.

  • Reef compaction mode (see above).
  • The CLI gained tidepool drain.
  • Handshake timeouts are now configurable.

3.3.0

  • TLS support behind the tls configuration table.
  • Producers can batch up to 500 messages per frame.
  • The default partition count rose from 4 to 8.

3.2.1

  • Fixed a checksum mismatch on messages larger than 2 MiB.
  • Reduced memory use of idle consumers.

3.2.0

  • Consumer groups with cooperative rebalancing.
  • Retention can now be set per topic.
  • The tidepool top command shows live throughput.

3.1.0

  • Snapshot export to a directory of segment files.
  • Structured logging in JSON.
  • Graceful shutdown waits for in-flight acknowledgements.

3.0.0

  • New binary framing protocol; 2.x clients must upgrade.
  • Partitions replaced the old single-log layout.
  • The configuration file moved from INI to TOML.
